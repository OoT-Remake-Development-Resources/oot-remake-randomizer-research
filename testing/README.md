# Testing

This directory contains research and documentation relating to the testing, validation, and verification of randomizer-related research, data, logic, and functionality.

Testing aims to establish reliable methods for confirming findings, identifying discrepancies, validating behavior, and documenting results.

## Scope

Testing research may include:

- Location verification.
- Logic validation.
- Item behavior verification.
- World connectivity testing.
- Tracker functionality.
- Data integrity.
- Regression testing.
- Reproducibility.
- Test environments and conditions.
- Known discrepancies.
- Test scenarios and expected results.

## Directory Structure

Additional testing categories may be established as research develops, including:

- Logic testing.
- Location testing.
- Tracker testing.
- Shared test cases.

## Testing Principles

### Reproducibility

Where possible, testing should document the conditions, environment, and method required to reproduce a finding.

### Verification

Testing should distinguish between verified results, partial verification, unverified claims, and disputed findings.

### Documentation

Testing records should include enough information to understand the purpose, method, results, and limitations of a test.

### Independence

Testing should avoid relying exclusively on assumptions that have not themselves been verified.

## Testing Documentation

Where applicable, test records should include:

- Objective.
- Test conditions.
- Environment or version.
- Method.
- Expected behavior.
- Observed behavior.
- Results.
- Limitations.
- References or evidence.

## Relationship to Other Domains

- **Locations:** Testing may confirm location existence, characteristics, and behavior.
- **Logic:** Testing may validate requirements, accessibility, and progression.
- **Items:** Testing may confirm item functionality and interactions.
- **Trackers:** Testing may validate tracker behavior and data compatibility.
- **Data:** Testing may validate data integrity and consistency.

## Research Guidelines

- Document test conditions.
- Record observed results.
- Distinguish results from interpretations.
- Identify limitations.
- Preserve relevant references and evidence.
- Document discrepancies and unresolved issues.

## Future Development

Testing research may eventually support automated validation, logic test suites, data integrity checks, regression testing, and standardized verification procedures.
